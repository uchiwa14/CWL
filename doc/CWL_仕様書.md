# CWL Ver1.0 仕様書

## 1. 概要
CWL (Chrome Workspace Launcher) は、Windows 11 上で Google Chrome の複数プロファイルを一括起動し、指定したモニタ上へ自動配置する AutoHotkey v2 製の業務用ランチャーです。業務開始操作で Chrome を起動・再利用し、業務終了操作で管理対象ウィンドウをまとめて終了します。

## 2. 対象環境
- OS: Windows 11
- 実行基盤: AutoHotkey v2.0
- ブラウザ: Google Chrome
- 依存ファイル: `CWL.ahk`, `config.ini`

## 3. 目的
- Chrome のプロファイルを複数起動して業務用ワークスペースを即座に構成する
- モニタ環境に応じて最適な配置位置を自動決定する
- 仕様変更を `config.ini` だけで反映できるようにする

## 4. 機能要件
### 4.1 設定読み込み
- `config.ini` を読み込み、アカウント数・URL・モニタ判定条件・レイアウト比率・ログ設定を取得する
- `Accounts` セクションの `Count` と `[Account1]` 〜 `[AccountN]` の数が一致しない場合はエラーとする
- 起動時に設定ファイルの不足セクション・余剰セクション・不正値を厳密に検出し、不整合がある場合はエラーとして処理を停止する

### 4.2 Chrome 起動・再利用
- Chrome 実行ファイルを自動検出する
- 指定されたプロファイルディレクトリで新規ウィンドウを起動する
- 既に「業務 URL」を開いており、かつ「対象プロファイル」である Chrome ウィンドウがあれば、そのウィンドウを再利用する（`account -> hwnd` の対応を明示的に管理する）

### 4.3 モニタ選択
- PCに接続されているすべてのモニタ情報（モニタ番号、作業領域の座標・サイズ等）を取得し、INFOログとして出力する
- CWLアプリ（GUI）が表示されているウィンドウ（モニター）を自動検知し、業務開始ボタン押下時にその同一モニタ上へブラウザを配置・展開する
- `DisplayMode` の値に応じて対象モニタを切り替える
  - `Auto`: CWLアプリが表示されている同一モニタを優先選択し、アプリが存在する画面内へブラウザを展開する（特定不可の場合は外付け/プライマリへフォールバック）
  - `App`: CWLアプリが表示されている同一モニタを明示的に選択する
  - `External`: 外付けモニタを優先し、なければノート PC へフォールバック
  - `Notebook`: ノート PC を使用
- モニタ幅が `ExternalMinWidth` 以上であれば外付けモニタと判定する

### 4.4 レイアウト配置
- 各アカウントの `X/Y/W/H` 比率から、対象モニタ作業領域内の矩形を算出する
- 算出された `X/Y/W/H` がモニタの作業領域内に収まる（画面外に出ない、合計比率超過による重なり崩れを防ぐクランプ）よう妥当性検証のルールを適用する
- 最低サイズを保証し、ウィンドウを移動・サイズ変更する

### 4.5 GUI / トレイ操作
- GUI から `業務開始` と `業務終了` を実行できる
- トレイメニューから同様の操作を実行できる
- 実行ログを GUI のステータス欄に表示する

### 4.6 業務終了
- 本ツールが起動、または再利用して制御したウィンドウ（`managedWindows`）のみを対象に、確認ダイアログ（対象一覧を表示）後に閉じる
- ユーザーが手動で別途開いた業務ウィンドウなどは終了対象に含めない
- 既に存在しないウィンドウは無視する

## 5. 入出力仕様
### 5.1 入力
- `config.ini`
  - `[General]`: URL, DisplayMode, ChromePath, LogEnabled, LogFile, WindowWaitMs, LaunchIntervalMs, ExternalMinWidth
  - `[Accounts]`: Count
  - `[AccountN]`: Name, Folder, X, Y, W, H

### 5.2 出力
- ログファイル: `CWL.log`（既定）
- GUI ステータス欄
- メッセージボックスによるエラー通知

## 6. 操作仕様
### 6.1 業務開始
1. `config.ini` を読み込む
2. PCに接続されているすべてのモニタ一覧情報をログ（INFO）に出力し、対象モニタを決定する
3. 既存の業務ウィンドウを再利用候補として収集する
4. 各アカウントについて、既存ウィンドウがあれば再利用し、なければ新規起動する
5. 配置矩形を算出し、ウィンドウを移動・アクティブ化する

### 6.2 業務終了
1. 管理対象ウィンドウを収集する
2. 確認ダイアログを表示する
3. ユーザーが「はい」を選択した場合のみ、対象ウィンドウを閉じる

## 7. 例外・エラー処理
- エラー分類を「致命的（Fatal）」「警告（Warn）」「情報（Info）」の3段階で明確化する
- Chrome 実行ファイルが見つからない、または設定ファイル読込失敗などの「致命的」なエラーは起動・処理を停止しダイアログを出す
- 一部のウィンドウ起動失敗や配置ミスなど処理の継続が可能なものは「警告」としてログに記録し、成功分は処理を継続する
- 例外が発生した場合はエラー分類に応じて適切に処理する

## 8. 非機能要件
- AutoHotkey v2 構文に準拠する（オブジェクトやプロパティの初期化・未定義チェックにおいて厳格な構文制約を遵守する）
- 複数 DPI 環境でも座標ずれしないように Per-Monitor DPI Aware を有効化する
- 画面の解像度・モニタ構成変更に対応できるように、レイアウトは比率指定とする
- 実行ファイル化（EXE 化）に対応する

## 9. 制約事項
- Chrome のプロファイルは `Folder` 値で識別するため、Chrome の表示名ではなく実際のプロファイルディレクトリ名を設定する必要がある
- ウィンドウサイズの最小値は 200x150 とする
- `Count` と `[AccountN]` セクション数は一致させる必要がある
